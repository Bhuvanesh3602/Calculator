=====================================================================
## 0. NON-NEGOTIABLE RULES
=====================================================================
1. UNIQUE VALUE PER PAGE. A bare form is thin content. Every page needs its own
   tool feature, analysis, worked examples and FAQs (section 4).
2. ACCURATE MATHS. Pure functions + unit tests + cited sources; rates/brackets
   carry an "as of" date. Wrong numbers kill trust and rankings.
3. SERVER-RENDER ALL TEXT (answer, formula, tables, FAQ). Calculator may be JS.
4. ONE PAGE = ONE INTENT = ONE PRIMARY KEYWORD. Merge variants (section 1).
5. LOCAL RULES PER COUNTRY (tax year, currency, bodies). Never mix US/UK rules.
6. Disclaimers: estimates only; not financial/medical/tax advice.
7. No fake reviews/authors/stats. No brand-name clones (Desmos, ADP, Bankrate,
   Calculator.net are trademarks/competitors - target the generic term).

## 1. HOW TO READ THE KEYWORD DATA (IMPORTANT)
=====================================================================
  - Identical volumes across variants (e.g. 673,000 on 20 loan/percent rows) =
    Keyword Planner GROUPED them. They are ONE demand pool - do NOT add them up
    and do NOT make 20 pages. One page, variants used as H2s/anchors/FAQs.
  - "Competition" (0-1) = ADVERTISER competition, NOT SEO difficulty. Judge SEO
    difficulty by looking at the actual top-10 results for each target.
  - CPC currency/location were not stated in the export. Treat as relative
    ranking and re-pull for US/UK/CA/AU before forecasting revenue.
  - "Score" column meaning unknown - ignored for ranking.
  - Rows with the literal word "Volume" (calculator, bmi, mortgage, compound
    interest group) lost their number in the paste. All are head terms and
    clearly large; re-export to confirm.
  - Priority metric used below:  VALUE = monthly volume x CPC  (revenue proxy)
    then adjusted for build effort, YMYL risk, and uniqueness potential.

Noise / ignore (garbled or irrelevant variants): "gra calculator", "a/g
calculator", "age c calculator", "apa reference calculator", "calculator kalori"
(Indonesian - only for a future ID/MY site), "ovu calculator" (fold into
ovulation), "mortization calculator" (typo - add as a misspelling variant on
the amortization page), "google calculator", "calculator app".

## 3. SEO-FRIENDLY PAGE TEMPLATE (EVERY PAGE)
=====================================================================
Title (<=60): "<Primary Keyword> (2026) - <Benefit>"  e.g.
  "Paycheck Calculator (2026) - Take-Home Pay by State"
Meta description (140-160): benefit + one number + modifiers from variants.
URL: /paycheck-calculator/  (country: /uk/paycheck-calculator/ etc.)

Order on page:
 1. H1 = primary keyword.
 2. ANSWER BLOCK (40-60 words, server-rendered) with a worked numeric example.
 3. Calculator (labels, defaults, instant results, shareable URL, reset,
    copy/print/CSV).
 4. Results: chart + table.
 5. How it is calculated: formula (text + symbols), variables, assumptions.
 6. 2-3 worked examples.
 7. UNIQUE ANALYSIS SECTION (section 4).
 8. Reference table (rates/limits/brackets) with "as of" date + source.
 9. Variant H2s: one short H2 per absorbed keyword variant, written as a
    natural question (e.g. "Is a car loan calculator the same as an auto loan
    calculator?") - captures long-tail without duplicate pages.
10. Common mistakes / tips.
11. FAQ (5-8 Qs; first sentence = direct answer).
12. Related calculators (descriptive anchors, 3-8 links).
13. Sources, "Last reviewed", reviewer, methodology link.
Length: 800-1,800 useful words beyond the tool.

## 6. TECHNICAL SEO CHECKLIST
=====================================================================
Crawl/index: HTTPS; one canonical host; self-canonical on all pages; robots.txt
(allow useful, block /api/ and param junk, list sitemaps); sitemap index split
by section with accurate <lastmod>; noindex internal search/print/filter
pages; hreflang en-US/en-GB/en-CA/en-AU/en-IN + x-default (reciprocal);
shared-result URLs (?amount=) canonical to clean URL.
Performance (mobile): LCP<2.5s, INP<200ms, CLS<0.1; static HTML; inline
critical CSS; defer JS; lazy-load charts; reserve ad slots (no CLS); AVIF/WebP;
Brotli; long cache.
UX: mobile-first, inputmode="decimal", no intrusive interstitials, calculator
visible above the fold (ads never push it down), WCAG AA, aria-live results.
E-E-A-T: About, Editorial policy, Methodology, Contact, named real authors and
credentialed reviewers (CPA/CFA/RD/clinician) on YMYL pages.
Stack: Astro or Next.js static; Tailwind; TypeScript calc libs in lib/calc/.

## 8. AEO - ANSWER ENGINE OPTIMISATION
=====================================================================
Goal: be cited by Google AI Overviews, ChatGPT search, Perplexity, Copilot,
Gemini, voice assistants.
  - Answer-first (numeric answer in first 60 words).
  - Question-form H2/H3 using real query phrasing from the keyword list
    (e.g. "How much is a $400,000 mortgage per month?").
  - One-sentence definitions; formula in text + symbols with variable key.
  - Tables/lists/steps (quotable); every stat has unit + date + named source.
  - "As of <Month Year>" on rates/limits; refresh yearly (Nov-Jan).
  - Original data tables (computed by us): paycheck by state, payment grids,
    tipping norms, CD/HYSA comparisons - publish as HTML tables + CSV; this is
    what AI engines cite.
  - Entity consistency (brand, authors, org facts) everywhere.
  - robots.txt: allow OAI-SearchBot, GPTBot, ChatGPT-User, PerplexityBot,
    ClaudeBot, Google-Extended, Applebot-Extended, bingbot (decide training vs
    search crawlers deliberately). No content behind JS/tabs/logins.
  - Bing Webmaster Tools + IndexNow (ChatGPT/Copilot lean on Bing).
  - Optional /llms.txt (cheap, unproven).
  - Track: weekly check of ~30 target questions in ChatGPT, Perplexity, Gemini,
    AI Overviews -> are we cited? Plus GA4 referrals from AI domains.
